# Consolidation & reflect: two-model head-to-head

The retain benchmark (this repo) scores the **extraction** half of a
memory pipeline. The **downstream** half — consolidation (merging
extracted facts into observations) and reflect (rebuilding mental-model
summaries) — has different physics: long inputs, schema'd merge/decide
outputs, and reasoning-model budgets.

This is a small operational study, not a leaderboard: one realistic
17-fact consolidation batch and one reflect prompt, built with the real
production prompt builders, run once per model per task through an
OpenAI-compatible gateway. Numbers from 2026-09-04.

## Consolidate (17-fact batch, strict JSON schema)

| | reasoning model A | thinking model B |
|---|---|---|
| Consolidation plan | 7 creates / 5 updates | 7 creates / 5 updates (identical) |
| Source coverage | 17/17 facts | 17/17 facts |
| Wall time | 28.5 s | 16.9 s |
| Output tokens | 1,515 (all content) | 2,995 (1,547 = reasoning tokens) |
| finish_reason | stop | stop @ 16K budget — **length-truncated @ 4K budget** |

**Key finding — the thinking budget is the failure mode, not quality.**
Given a production-size output budget, both models produced the *same*
consolidation plan. But at a modest 4K output budget, the thinking model
burned 78% of it on reasoning and returned zero parseable JSON
(`finish_reason=length`). Reasoning-heavy models on consolidation duty
need budgets sized for the thinking tax, or they fail silently — the
JSON simply never arrives.

## Reflect (mental-model rebuild prompt)

| | reasoning model A | thinking model B |
|---|---|---|
| Output quality | accurate, concise prose | accurate, richer (tables, summary) |
| Wall time | 7.2 s | 4.2 s |
| Output tokens | 349 (0 reasoning) | 695 (276 reasoning) |

At reflect's small payload size the thinking tax is negligible, the
thinking model is ~1.7x faster, and its output is arguably nicer.

## Operational takeaway

Split the lanes by *budget physics*, not by leaderboard rank:

- **Consolidate** → the model whose tokens all land in content
  (reasoning-taxed models risk silent truncation on big batches).
- **Reflect** → the fast thinking model (tax rounds to zero at this
  payload size).

## Method notes

- Payloads generated by the target system's real prompt builders
  (`build_consolidation_system_prompt`, `build_final_system_prompt`).
- Strict `json_schema` response format accepted by both models.
- Reasoning tokens counted from provider usage
  (`completion_tokens_details.reasoning_tokens`).
- Single-run study: wall-clock numbers are directional; the
  creates/updates/deletes plans and the truncation behavior were
  deterministic across the runs observed.
